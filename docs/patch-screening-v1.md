# NEXUS Patch Screening V1

Follow-up to [Coding Benchmark V1.1](coding-benchmark-v1.md). Primary Qwen2.5-Coder 14B and fallback 7B, pinned to full observed model digests. This is an intermediate constrained patch-proposal benchmark, **not** OpenCode, general Python execution or repository editing. No generated Python is compiled or executed. An explicit AST interpreter evaluates a small, finite subset of Python over synthetic, bounded data. It has no filesystem, network, subprocess, dynamic calls or repository tools; unfamiliar syntax is rejected. This restriction can penalize valid Python solutions outside its subset and does not prove semantic equivalence to full Python. Candidate text is saved as data only in report artifacts for human review and omitted from console output.

Three synthetic regressions based on public evaluator helper contracts: duplicate key rejection (5 cases), nonempty text validation (6), unique string list validation (8). The expected results and reference fixes are fixed before generation. Prompts include broken function and specification, not test cases or reference solution. The reference fixes must pass and regressions must fail CPU preflight; six prohibited syntax samples are also checked. All three tasks must pass all their cases with GPU verified on each for qualification. No automatic retry or merge.

Manual GitLab pipeline on experiment/gpu-capability-probe, input run_gpu_smoke=patches. Two independent GPU jobs, each capped at 20 minutes, at most 40 raw runner minutes before billing multiplier. Run only if included compute budget is sufficient. Same pinned CUDA image and verified Ollama release, separate unscored warmup, 150s per request, 780s benchmark timeout, temperature 0, seed 42, context 4096. Reports distinguish infrastructure incompleteness, wrong answers and rejected language constructs. Read reports before deciding whether to proceed. No paid services, no changes to main, no generated patch execution or credential access. OpenCode integration requires a separately reviewed tool policy and genuine isolation; this phase does not install it.

CPU preflight is not evidence of model performance or secure general-purpose sandboxing.

Its list proposal uses a forbidden generator and all(); its logic appears correct on inspection, but was not scored.

Only replay mode adds zero-argument set and bounded string additions to an actual set. The original GPU benchmark retains its original grammar and scores. Replay must still reject prohibited syntax and fail a deliberately inverted membership check. This is a post-hoc diagnostic, not a new blind benchmark or a 3/3 qualification claim. No model code execution, no additional GPU runs. 14B remains the provisional candidate for a separately validated read-only OpenCode pilot; 7B is not validated as a patch fallback.
